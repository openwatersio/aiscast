# Higher-end SDRs for AIS: Airspy, HydraSDR, SDRplay, HackRF, LimeSDR, coherent dongles

Researched 2026-08-22. Companion to [sdr-receivers.md](sdr-receivers.md), which covers the RTL-SDR family; this file carries the device-by-device detail for everything above it. Sources are manufacturer pages, datasheet PDFs, the AIS-catcher source tree and GitHub API, and two independent bench measurements. Reddit and several vendor forums return 403 to automated fetches and were not consulted.

## Bottom line

- AIS needs ~75 kHz of capture (both channels sit ±25 kHz of a single 162.000 MHz centre; AIS-catcher tunes one centre and splits the channels with a ±25 kHz rotation in DSP, `Source/Application/Receiver.cpp:115`, `Source/DSP/Model.cpp:31`). Every SDR below has orders of magnitude more bandwidth than that, so bandwidth is never the selection criterion; noise figure, blocking performance, frequency stability and driver friction are.
- On an independent bench (Tech-ni-shn, Aug 2026, 136 MHz, 2400 Hz SSB, uncalibrated) the **$35 RTL-SDR Blog V3 measured the most sensitive device at VHF**: V3 −136.0 dBm > Airspy Mini −133.9 > Airspy HF+ Discovery −132.5/−132.8 > RTL-SDR Blog V4 −132.0. rtl-sdr.com's own summary ("all around −133 dBm") flattens a 4 dB spread in exactly the band that matters.
- Field message-count deltas between good SDRs run −10% to +15% (AIS-catcher discussions #75, #333); the only rigorous lab NF table (Libre Space/ESA) puts SDRplay RSPduo at 2.1 dB @ 145 MHz, RTL-SDR V3 5.8, Airspy Mini 7.1, HackRF ~11, LimeSDR Mini 11.1 as shipped (~6 board-only; the 11.1 was traced to a scratch in the case paint). SDRplay has the best VHF NF yet users still report RTL-SDRs matching or beating it on decoded counts.
- Where higher-end hardware genuinely earns its place: RF-hostile sites. An Airspy's 35 dBm IIP3 and 12-bit converter, or an SDRplay's 120–250 MHz preselector, buy blocking performance near strong FM/DAB/pager transmitters that no RTL-SDR sensitivity recovers.
- Software rivals hardware: AIS-catcher's coherent default model gives 2–3× over non-coherent decoders, and the v2 engine (`-m 11`) adds another 4–8% at 45% less CPU ([discussion #607](https://github.com/jvde-github/AIS-catcher/discussions/607)).

## Notes that matter for a guide

**SDRplay on Linux.** API 3.15 (May 2024, last release) is a closed binary plus mandatory daemon, installed by an interactive `.run` that requires `dpkg` and a reboot; arm64/armhf/amd64 only. AIS-catcher's official Linux `.deb` packages do **not** include working SDRplay support (verified by inspecting v0.70's arm64 deb: the `HASSDRPLAY` string is the `Unavailable` stub from `Source/Device/SDRPLAY.h`), Windows gets a dedicated SDRPLAY zip, and Docker images exclude SDRplay entirely. Install the API, then build from source. Most likely failure: `shm_open: No such file or directory` / `SDRPLAY: API v3.x not running` / segfault when `sdrplay.service` is not running ([issue #575](https://github.com/jvde-github/AIS-catcher/issues/575)). RSPs upsample 2304K→3072K internally and cost more CPU than an RTL-SDR at 1536K; budget a Pi 4/5. RSP1A and RSPdx are discontinued; only RSP1B, RSPdx-R2, RSPduo ship new.

**HackRF.** It does have a front-end amp (~11 dB MGA-81563 gain block behind lossy diode switches; libhackrf's "lna" is the IF stage). Great Scott Gadgets' own docs never call it a poor receiver; that verdict is rtl-sdr.com's ("simply in a lower league of RX quality"). HackRF One is no longer manufactured (replaced by HackRF Pro, shipped end-2025). Sub-$150 "HackRF One" units are untested clones GSG found to fail QC across the band.

**Lime Microsystems** is an active UK company (Companies House 05380695: active, accounts filed May 2025, confirmation statement March 2026); "financial trouble" claims have no citable source. LimeSDR USB was revived March 2025 ($689); LimeSDR Mini v1 stays retired.

**Frequency stability beats sensitivity.** Measured decode falloff starts at ±1.5–2.5 ppm; `-go AFC_WIDE on` (default) tolerates ±10 ppm. Every device above has a TCXO except HackRF One (±20 ppm ≈ ±3.2 kHz at 162 MHz).

**Signal levels are not comparable across devices.** AIS-catcher scales SDRplay integers by 32768 and RTL-SDR bytes differently; the same ship reads −11 dB on an RTL-SDR V4 and −85 dBm on a dAISy-catcher ([#155](https://github.com/jvde-github/AIS-catcher/discussions/155), [#563](https://github.com/jvde-github/AIS-catcher/discussions/563)).

**Second dongle.** The only additive use is the long-range C/D pair at 156.800 MHz: `AIS-catcher -d serial1 -v -d serial2 -c CD -v -N 8100`.
