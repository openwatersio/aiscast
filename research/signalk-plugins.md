# Signal K AIS plugins and server API

Researched 2026-08-20 from published npm tarballs, `@signalk/server-api` types, `signalk-server` 2.31 source, and issue trackers. Informs the design of the `signalk-aiscast` plugin. Weekly downloads are for 2026-08-13 → 19.

## Headline findings

- Two archetypes exist and nothing does both: **raw-sentence relays** (`app.on('nmea0183')`, regex `!AIVDM`, forward bytes; `ais-forwarder`, `signalk-aprsfi-ais-reporter`) and **decoded-model bridges** (`app.getPath` / `app.handleMessage`; `signalk-aisstream`, `shipsio`, `@signalk/aisreporter`). `shipsio` is the only bidirectional one (POST own vessel, get neighbours back) and does it badly (polls `localhost:3000` over HTTP with no auth).
- The operational complaints are uniform across the ecosystem: no reconnect after network loss (`ais-forwarder` #6, open since 2021), listeners leaking on every config save (`ais-forwarder` #3), silent subscriptions that open but never deliver (`signalk-aisstream` #33), fixed-interval retries turning a 429 into a 2.7-day outage (`signalk-mareas-ihm` #37), own vessel coming back from a network feed and triggering collision alarms against itself (`signalk-mareas-ihm` 2.11.2), baconjs prototype mismatch making `app.streambundle` silently never emit on Venus OS (`aisreporter` #46).
- Auth everywhere is a shared secret in a URL, body field, or header (API key, username:password, HMAC in `signalk-web-tracker`); no plugin uses a keypair. Offline buffering exists in two plugins: `signalk-mqtt-gw` (`mqtt-jsonl-store` in the data dir, QoS 1) and `signalk-web-tracker` (`node:sqlite`, per-destination watermarks, advance only on ACK).
- aisstream.io is the loudest complaint in the community: `aisstream/issues` has ~196 open, including "Dead project, the need is a FOSS alternative" (#218). `signalk-aisstream` (62/wk) and `signalk-mareas-ihm` (920/wk) both consume it.

## Server API facts that matter

- `app.on('nmea0183', fn)` fires for every inbound sentence (string, trimmed, no CRLF), emitted by `@signalk/streams/nmea0183-signalk` on both `app` and `app.signalk`, before parsing, unless the provider sets `suppress0183event`. `nmea0183out` is never emitted by the server; it is a convention for plugins (`signalk-to-nmea0183`, `signalk-n2kais-to-nmea0183`) and the TCP 10110 server listens to both. So listening on both catches 0183 and N2K-derived AIS. Plugin `on`/`emit` are bound per plugin id through `wrappedEmitter.bindMethodsById`, but register and remove on the same emitter.
- `app.handleMessage(id, delta)`: context `undefined`/`vessels.self` is rewritten to self; any other context passes through. With a `source` object, `label` is forced to the plugin id unless already a safe string, then `$source ||= getSourceId(source)` (`label.talker` for NMEA0183, bare `label` for `type: 'plugin'`); with no source, `$source ||= pluginId`. An explicit `$source` string is kept as given. `timestamp ||= now`.
- `@signalk/nmea0183-signalk`: `new Parser().parse(sentence): Delta | null`, stateful for multipart VDM, strips TAG blocks. VDM hook contexts: `vessels.` for 1,2,3,5,18,19,24; `atons.` for 4 and 21; `aircraft.` for 9; `meteo.` for ASM weather. Paths: root `{mmsi}`/`{name}`, `navigation.position/speedOverGround/courseOverGroundTrue/headingTrue/rateOfTurn/state/destination.*/specialManeuver`, `design.length/beam/draft/aisShipType`, `sensors.ais.class/fromBow/fromCenter/…`, `atonType`, `offPosition`, `virtual`. Position is emitted only when `lat && lon` are truthy (Null Island dropped, 91/181 sentinels not).
- `getSelfPath('mmsi')`, `getPath(ctx + '.navigation.position')` → `{value, $source, timestamp}`, `selfId`, `selfContext`, `getDataDirPath()` (call in `start()`, not at construction), `setPluginStatus`/`setPluginError` (no dedupe; every call re-emits a server event), `savePluginOptions(configuration, cb)`, `readPluginOptions()` returns the whole file. `registerWithRouter` mounts at `/plugins/<id>` admin-only; `router.access('readonly').get(...)` opens a route. `stop()` may return a Promise; the server awaits it before restarting on config save.
- Server settings already handle stale targets (`pruneContextsMinutes`, default 60) and source preference per path (`sourcePriorities`); a plugin should not reimplement either.
- `package.json`: keyword `signalk-node-server-plugin` (discovery), `signalk-category-ais` (app store), top-level field `signalk-plugin-enabled-by-default`, optional `"signalk": {displayName, appIcon}`. Server requires Node ≥ 20; Node 20 has no global `WebSocket`, so use `ws`.

## Rules distilled for our plugin

1. Relay from `nmea0183` plus `N2KAnalyzerOut` (re-encode the AIS PGNs ourselves); do not listen on `nmea0183out`, where `signalk-vessels-to-ais` re-emits network-injected targets. Remove listeners on the same emitter in `stop()`, and make a late `start()` notice that `stop()` ran meanwhile.
2. Exponential backoff with jitter, longer on 429/403, reset on first success; a silence watchdog, not just a connection check; status line shows last-received age.
3. Filter own MMSI on every inbound path; drop our own echoes; guard the `signalk-n2kais-to-nmea0183` loop.
4. Use the server's own parser for injected targets so paths, contexts, and types are byte-identical to VHF-received AIS (no `name` as a bare string, no wrong `eta` type).
5. Write-ahead queue in `getDataDirPath()`, advance only on ACK.
6. No `app.streambundle`; poll `getSelfPath` or use `subscriptionmanager`.
